 # История работы над проектом Brief OS

## 2026-08-21 — Подготовка ТЗ и плана

### Запрос

Юрий уточнил правила приложения:

- клиент занимается только заполнением брифов;
- дополнительных разделов и функций для клиента нет;
- бриф возвращается менеджеру;
- менеджер может вернуть бриф далее дизайнеру;
- ссылка должна иметь формат `brief.yuriybevov.ru/brief/<token>`;
- необходимо создать подробное ТЗ в папке проекта;
- необходимо разбить разработку на этапы;
- гайды из `AI-design-systems/guides` нужно скопировать в проект;
- вся история работы ведётся в этом файле;
- после каждого этапа создаётся отчёт и ожидается согласование перехода дальше.

## 2026-08-21 — Уточнение модели брифа и открытых вопросов

### Добавленные требования

1. Бриф определяется как список вопросов с ответами конкретного пользователя системы или клиента.
2. Создание, изменение статуса, редактирование, отправка, возврат, принятие, создание ссылок и все остальные действия с брифом сохраняются в истории проекта.
3. Каждый бриф и каждая его версия доступны сотрудникам для просмотра на любом этапе жизненного цикла.
4. Клиент не видит историю изменений.
5. Обязательность полей проекта, брифа и чеклиста назначается их создателем.
6. Разрешаются безопасные форматы файлов; точный whitelist будет уточнён после проверки инфраструктуры.
7. При возврате указывается получатель и может быть добавлен комментарий. Возврат возможен менеджеру, дизайнеру или другой разрешённой роли.
8. Редактировать бриф может только текущий адресат. Предыдущий участник после передачи получает режим просмотра.
