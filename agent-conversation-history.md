## 2026-08-21 — Клиентская ссылка и согласование брифа

### Основание

Юрий уточнил корректную логику работы с брифом: бриф является набором вопросов к согласованию. Пользователь создаёт клиентскую ссылку на выбранный или созданный бриф, клиент заполняет бриф по ссылке и нажимает «Согласовать». После этого отправителю визуально отображается готовность брифа.

### Выполнено

1. Удалена неверная логика «Отправить менеджеру».
2. Статусы брифа заменены на:
   - Черновик;
   - Ожидает заполнения;
   - Заполнен.
3. В карточке брифа добавлена кнопка «Создать ссылку».
4. Для брифа сохраняется список клиентских ссылок с токенами.
5. Добавлен публичный маршрут `/brief/<token>`.
6. Публичная страница показывает вопросы конкретного брифа без основного интерфейса приложения.
7. На публичной странице пользователь заполняет ответы и нажимает кнопку «Согласовать».
8. После согласования ответы сохраняются во временное client-side хранилище, а в рабочем интерфейсе бриф получает статус «Заполнен» и визуальную пометку «Бриф заполнен».
9. Для старых записей в `localStorage` добавлена мягкая нормализация, чтобы прежний статус `sent_to_manager` не ломал интерфейс.

### Проверки

1. `npm run build` — production build прошёл успешно.
2. Проверено, что строки «Отправить менеджеру» и `sent_to_manager` удалены из кода приложения.

### Состояние

Интерфейсный сценарий бриф → клиентская ссылка → заполнение → согласование → готовность реализован. Ограничение сохраняется: до подключения PostgreSQL и server API ссылка работает как frontend-прототип на `localStorage`, а не как реальная ссылка для другого устройства или браузера.

## 2026-08-21 — Ответы брифа на уровне клиентской ссылки

### Основание

Юрий уточнил, что один и тот же бриф может быть отправлен разным клиентам. Поэтому заполненность и ответы должны принадлежать не брифу как шаблону, а конкретной клиентской ссылке, которая была отправлена клиенту.

### Референсы

1. Google Forms разделяет форму и ответы; ответы можно смотреть индивидуально.
2. Typeform хранит ответы как отдельные submissions и позволяет открывать индивидуальный ответ.

### Выполнено

1. Модель ответов перенесена с уровня брифа на уровень конкретной клиентской ссылки.
2. Каждая ссылка теперь имеет собственный статус:
   - Ожидает заполнения;
   - Заполнен.
3. Один бриф может иметь несколько клиентских ссылок.
4. Каждая ссылка хранит собственные ответы и дату заполнения.
5. В карточке брифа отображается количество ссылок и количество заполненных ссылок.
6. Каждая ссылка визуально показывает свой статус.
7. Для заполненной ссылки ответы отображаются отдельно под этой ссылкой.
8. При переходе по заполненной ссылке `/brief/<token>` отображается read-only результат заполнения, а не форма повторного заполнения.
9. Для старых данных добавлена миграция: если ответы были сохранены на уровне брифа, они переносятся в первую ссылку как заполненная выдача.

### Проверки

1. `npm run build` — production build прошёл успешно.

### Состояние

Логика стала ближе к реальной модели форм: бриф является шаблоном вопросов, а каждая клиентская ссылка является отдельным экземпляром заполнения. До подключения server API и базы данных это всё ещё работает в рамках `localStorage`-прототипа.
