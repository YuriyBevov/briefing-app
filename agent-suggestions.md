 # Предложения и вопросы проекта Brief OS

Этот файл не заменяет техническое задание. Предложения не внедряются без отдельного согласования.

## Согласованные решения

1. Бриф можно удалить из рабочего интерфейса, но удаление выполняется мягко: история проекта, версии брифа и связанные записи не удаляются.
2. Без явного действия удаления система ничего не удаляет.
3. История изменений должна хранить не только факт действия, но и перечень изменённых полей с предыдущими и новыми значениями, если это безопасно и применимо.
4. При возврате брифа комментарий с причиной возможен, но не обязателен.
5. Временный пароль `admin/admin` после первого входа менять принудительно не нужно.
6. Подтверждающие диалоги и расширенный audit log для важных действий пока не входят в обязательную реализацию.
7. Email-уведомления в MVP не нужны; достаточно внутренних уведомлений.
8. Структуру и данные брифа может редактировать только текущий конечный адресат.
9. История брифа доступна только сотрудникам с соответствующим правом.
10. Публичная ссылка может иметь срок действия 30 дней. Истечение ссылки не удаляет бриф, ответы, версии или записи истории проекта; сотрудник может просматривать сохранённые данные в системе.

## Технические уточнения

- Для удаления брифа используется `deleted_at`, `deleted_by` и причина удаления, если она будет добавлена в интерфейс.
- Удалённый бриф скрывается из обычного списка, но остаётся доступным сотрудникам в истории проекта с пометкой «Удалён».
- Истёкшая публичная ссылка открывает сообщение о завершении доступа и не позволяет редактировать форму.
- Повторная ссылка на тот же бриф создаётся сотрудником с соответствующим правом.
